# 일상 운영과 권한 모델

## 역할별 운영 범위

SOAR는 운영 권한과 탐지 대상 권한을 분리합니다. 일반 사용자가 보안 운영 객체를 직접 조회하거나 정책을 바꾸지 않아도 백그라운드 탐지는 동작하도록 설계합니다.

| 기능 | 관리자 | 운영자 | Sites 게스트 | 일반 사용자 |
|---|:---:|:---:|:---:|:---:|
| 대시보드·감사 로그 조회 | 가능 | 가능 | 불가 | 불가 |
| 위협 시뮬레이터 | 가능 | 가능 | 불가 | 불가 |
| 정책·라우트 변경 | 가능 | 제한 | 불가 | 불가 |
| 스케줄 설정 | 가능 | 불가 | 불가 | 불가 |
| Drift 복구 | 가능 | 불가 | 불가 | 불가 |
| 인바운드 대응 수신 | 가능 | 가능 | 제한된 지점만 | 불가 |

## 운영 화면의 기본 흐름

### 대시보드

보안 점수, 최근 위협 타임라인, 채널별 요약, 심각도 필터, 감사 로그를 확인합니다. 로그 상세 화면에서는 탐지 정책, 유입 채널, 대상 리소스, 누적 횟수와 감사 추적 정보를 확인할 수 있습니다.

### 위협 시뮬레이터

실제 업무 데이터에 영향을 주지 않는 사전 정의 시나리오로 Platform, Data, Logic, Identity, External Signal 영역의 흐름을 점검합니다. 운영 전환 전에 이벤트 발행, 정책 매칭, 감사 기록과 알림 결과를 확인하는 용도로 사용합니다.

### 정책 매퍼

정책별 임계치와 대응 액션을 확인하고, 조직의 허용 범위에 맞게 조정합니다. 패키지 기본값과 런타임 설정이 달라지면 Drift 상태를 확인한 뒤 승인된 항목만 Reconcile합니다.

### 라우트 관리자

정책 코드, 심각도, 우선순위와 채널을 기준으로 알림 경로를 관리합니다. 동일 이벤트의 반복 알림은 중복 억제 창으로 제어하고, 일시적 전송 실패는 전달 원장과 제한된 재시도로 추적합니다.

### Teams 카드 버튼과 Site callback 주소

Teams 카드의 버튼은 두 종류의 목적지를 가질 수 있습니다.

- `사용자 상세 보기`: 로그인된 Salesforce 조직 화면으로 이동하는 조회 링크
- 보안 대응 버튼: Site 기본 주소 뒤에 `/services/apexrest/api/security/action`이 붙은 공개 REST callback

두 번째 링크가 Site 홈 화면이 아닌 REST 경로로 보이는 것은 정상입니다. 버튼 자체가 Site 페이지를 보여주기 위한 것이 아니라, 단기·단회 callback code와 승인 binding을 패키지 endpoint에 전달해 인바운드 요청을 처리하기 때문입니다. 브라우저의 GET 요청에는 HTML 결과 화면이 반환되고, 서버 간 호출에는 JSON 응답이 사용됩니다.

파괴적 액션은 독립 관리자 승인 전에는 카드에 실행 버튼이 나타나지 않습니다. 테스트와 운영 모두 요청자·대상·승인자를 구분하고, 관리자 계정을 테스트 대상에 직접 지정하지 않습니다. URL의 query 값은 재사용·공유하지 말고 새 카드로 다시 발송합니다.

### 스케줄 관리자

로그 보관, 정리, 감사 폴링과 실패 재전송 등 필요한 백그라운드 작업만 활성화합니다. 중복 등록 여부와 다음 실행 상태를 확인하고, 조직의 보존 정책에 맞춰 주기를 검토합니다.

## 운영 원칙

- 파괴적 대응은 승인·권한·감사 원장을 함께 확인합니다.
- 외부 채널의 URL과 인증 값은 Salesforce Named Credential에서 관리합니다.
- 정책을 바꾼 뒤에는 시뮬레이터와 감사 로그로 의도한 결과를 확인합니다.
- 일반 사용자에게 운영 권한 집합을 광범위하게 할당하지 않습니다.
- 사용하지 않는 Zero-Login 지점과 스케줄은 비활성화합니다.

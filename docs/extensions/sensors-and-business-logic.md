# 센서와 비즈니스 로직 평가

## 목적

고객 조직의 Opportunity, Order, Contract, Account 등 업무 객체에서 보안 관점의 변경을 감지하고, SOAR 정책 엔진이 평가할 수 있는 표준 신호로 전달합니다.

## 지원 계약

| 계약 | 사용 위치 | 결과 |
|---|---|---|
| `soarpkg.ISecuritySensor` | 객체 변경 감지 계층 | 변경 내용을 표준 보안 이벤트로 변환 |
| `soarpkg.SecuritySensorAdapter` | 센서와 패키지 이벤트 흐름 사이 | 정책 평가·감사·알림 파이프라인으로 전달 |
| `soarpkg.Sec` | 기존 업무 로직의 명시적 평가 지점 | 정책 코드·심각도·문맥을 평가 흐름에 전달 |

## Subscriber 담당 범위

1. 어떤 객체와 변경이 보안 신호인지 정의합니다.
2. 고객 조직의 업무 의미를 정책 코드와 심각도로 매핑합니다.
3. 개인 정보나 불필요한 원문을 문맥에 넣지 않고, 감사에 필요한 식별자만 선택합니다.
4. Sandbox에서 정상·위반·예외·중복 이벤트를 검증합니다.

## 처리 및 보안 조건

- 센서는 원본 업무 트랜잭션을 불필요하게 지연시키지 않도록 얇게 유지합니다.
- 신호 생성과 실제 대응 실행을 분리합니다.
- 동일 변경이 반복 감지될 수 있으므로 이벤트 키와 중복 억제 기준을 정의합니다.
- 파괴적 대응은 센서가 직접 수행하지 않고 정책·승인 흐름에 위임합니다.
- 고객 객체의 `with sharing`와 필드 보안 원칙을 확장 코드에도 적용합니다.

## 비즈니스 로직 평가 지점

기존 업무 서비스가 “고율 할인”, “승인 없는 단계 변경”, “민감 고객 정보 접근”처럼 업무 의미를 가장 잘 아는 순간에 평가 계약을 호출할 수 있습니다. 이 호출은 정책 판단과 감사 흐름을 시작하는 용도이며, 업무 로직에 보안 대응 구현을 직접 섞는 용도가 아닙니다.

## 성공·실패 기준

| 상황 | 기대 동작 |
|---|---|
| 유효한 신호 | 정책 평가, 감사 기록, 등록된 채널 알림 |
| 정책 미매칭 | 조직의 기본 정책과 감사 설정에 따른 기록 |
| 중복 신호 | 중복 억제 기준에 따라 재평가 또는 건너뜀 |
| 외부 전송 실패 | 전달 원장 기록과 제한된 재시도 |
| 패키지 처리 장애 | 원본 업무 트랜잭션과 분리된 실패 기록·운영 알림 |

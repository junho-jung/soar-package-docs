# 외부 SIEM/SOAR·정책·브랜딩

## 외부 SIEM/SOAR 연동

외부 관제 시스템은 SOAR가 제공하는 보안 이벤트와 대응 계약을 이용해 다음 흐름을 구성할 수 있습니다.

`외부 신호 수신 → 정책 평가 → 대응 요청 → 승인 대기 또는 실행 → 결과 조회 → 감사 원장`

공개 계약은 “어떤 액션이 가능한지”, “승인이 필요한지”, “요청을 어떻게 식별하는지”, “결과가 어떤 상태로 돌아오는지”를 정의합니다. 인증 방식, 조직 도메인, 실제 요청 주소와 payload 값은 설치 버전과 고객 조직의 보안 정책에 맞춰 별도로 구성합니다.

### 외부 연동 담당 체크리스트

- [ ] 전용 Integration User와 최소 권한 사용
- [ ] Named Credential 또는 승인된 인증 저장소 사용
- [ ] 요청 ID로 중복 실행 방지
- [ ] 파괴적 액션의 승인 필요 여부 확인
- [ ] 2xx·4xx·5xx·timeout 상태별 재처리 정책 정의
- [ ] 외부 시스템과 SOAR 양쪽에 감사 상관관계 ID 보존
- [ ] 인증 정보와 원본 응답을 로그에 남기지 않음

## 정책과 채널 확장

정책 매퍼에서 패키지 기본 정책의 임계치·심각도·대응 액션을 조직 기준으로 조정할 수 있습니다. 라우트는 정책 코드와 심각도에 따라 Teams, Slack, 이메일 또는 등록된 외부 채널로 분기합니다.

정책을 변경할 때는 다음을 기록합니다.

- 변경 이유와 승인자
- 변경 전·후의 의미
- 적용 범위와 예상 영향
- 원복 기준과 시뮬레이션 결과

Drift가 발생하면 무조건 기본값으로 덮어쓰지 말고, 의도된 조직 설정인지 확인한 후 Reconcile합니다.

## 결과 화면과 브랜딩

Zero-Login 결과 화면은 조직의 브랜드명·색상·로고·안내 문구를 적용할 수 있습니다. 패키지가 제공하는 HTML 결과 화면 계약을 확장할 때에도 다음 원칙을 지킵니다.

- 실행 상태와 승인 상태를 숨기지 않음
- 감사 추적 ID를 운영자가 확인할 수 있음
- 민감한 대상 정보는 최소화하거나 마스킹함
- 외부 입력을 HTML로 그대로 렌더링하지 않음
- 모바일·다크 모드·접근성 기준을 함께 검증함

`soarpkg.ISecurityActionHtmlRenderer`와 같은 렌더링 계약은 화면 표현을 확장하는 용도입니다. 인증·승인·실제 대응 로직을 화면 렌더러에 넣지 않습니다.

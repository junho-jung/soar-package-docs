# 검증 결과와 품질 기준

## 검증 스냅샷

아래 수치는 개발·베타 검증 스냅샷이며, 공개 릴리즈 보증이나 특정 고객 조직의 SLA를 의미하지 않습니다.

| 검증 영역 | 결과 |
|---|---:|
| 핵심 기능 평가 케이스 | 45/45 통과 |
| 기능 모듈 | 10개 영역 |
| Subscriber 통합 테스트 | 9/9 통과 |
| Subscriber 테스트 커버리지 스냅샷 | 87% |
| 프로젝트 커버리지 운영 기준 | 80% 이상 유지 |

## 검증 시나리오

- 설치 후 관리자·운영자·게스트 권한 분리
- Setup & Health Center의 설정 누락 및 복구 흐름
- 대시보드 KPI, 타임라인, 감사 로그와 CSV 조회
- 정책 임계치 변경, Drift 감지와 선택적 Reconcile
- 알림 라우팅, 중복 억제, 제한된 백오프 재시도
- 5개 보안 채널 시뮬레이션과 이벤트 흐름
- Zero-Login의 승인 대기, 단일 사용과 링크 미리보기 방어
- 외부 연동 계약과 결과 상태 처리
- 일반 사용자 무권한 탐지와 운영자 권한 격리

## 품질 게이트

기능 변경은 다음 순서로 검증합니다.

1. 제공자 개발 조직에서 소스·Apex·UI 동작 검증
2. 패키지 형태와 Subscriber 확장 호환성 검증
3. 필요한 경우 관리 패키지 설치 검증
4. UI 화면과 운영 흐름을 스크린샷으로 확인
5. 테스트 통과율, 커버리지와 문서 상태 확인

프로젝트 규칙은 테스트 커버리지 80% 이상을 유지하는 것입니다. 단순히 수치만 맞추지 않고, 탐지·승인·실패·복구 경로가 실제로 검증되는지를 함께 확인합니다.

## 포트폴리오 증빙 공개 원칙

현재 공개 레포는 기능 평가 요약, 아키텍처, 품질 게이트와 운영 시나리오를 중심으로 구성합니다. Org 화면 캡처는 화면 데이터의 완전한 비식별성을 별도 확인한 뒤 필요한 경우 추가합니다.

검증 자료는 제품의 설계 의도와 운영 가능성을 보여주는 보조 증빙이며, 내부 소스나 원본 로그의 대체물이 아닙니다.
